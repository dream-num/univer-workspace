# Agent 与 DSH 的浏览器传输边界

[English](agent-transport-boundary.md) | 简体中文

## 产品模型

Workspace Agent 是单人应用，每个运行实例只有一个当前 Workspace 账号。
切换账号是全局操作，所有已打开的页面都跟随新账号，标签页不保留独立账号身份。

不同账号的会话、附件和索引仍保存在各自的运行目录中。这用于组织操作者的数据，
并不把本地 DSH 应用变成多租户服务或操作系统沙箱。

## 职责

| 所有者 | 负责 |
| --- | --- |
| DSH | 本地浏览器认证、RPC、WebSocket 多路复用与重连、原生下载、上传载体、Session 附件回执 |
| Agent core | Workspace OAuth、当前账号、账号运行目录和服务生命周期、切换期间的就绪状态、全局账号变化后的页面刷新 |
| Workspace 能力插件 | 产品 API 调用、Space 注册、文档工具、Viewer 装配，以及通过 Workspace 执行远端权限检查 |
| Workspace Server | 远端身份、ACL 和文档操作的权威校验 |

浏览器的 DSH 认证 Cookie 与保存在服务端的 Workspace 凭据分别归不同层所有。
切换 Workspace 账号不会撤销 DSH 浏览器会话。页面通过 DSH 公开的连接状态订阅感知变化，
读取 `/auth/connection/status`。恢复期间用原生模态对话框暂停旧页面交互，包括键盘焦点和已经打开的浮层。
账号运行时变化后，对话框保留到用户确认“刷新页面”；导航前再次检查就绪状态。
同一运行时的普通重连完成后自动解除暂停。恢复的页面执行相同检查。
DSH 浏览器会话过期时提示刷新以重新登录。短暂失败在限定窗口内重试，超时后保持暂停并提供“重新检查”。
正常空闲页面不轮询。确认只刷新当前标签页，当前账号已经全局切换。

## 实现

- `WorkspaceAuthProvider` 在暴露下一账号前等待原账号服务退出，并恢复对应的数据目录。
- `RuntimeWebServer` 仅在账号服务不可用时返回 503，不要求自定义页面版本请求头或查询参数。
- 页面启动时的运行时版本只用于判断是否刷新，不是逐请求授权令牌，也不是标签页独立身份。
- `connection-recovery.ts` 订阅 `connection.state` 和 `pageshow`；WebSocket、重连循环和浏览器认证仍由 DSH 负责。
- 原生 Fetch、WebSocket、下载 anchor 和 DSH 上传 Worker 保持原样。
  应用不安装 `__DSH_TRANSPORT__` 或 `__DSH_FILE_UPLOAD__` 覆盖实现。
- 附件保留 DSH 的 Session 身份和回执生命周期，不创建远端 Workspace 文档。
  Workspace 工具仍使用服务端认证客户端，保留中的操作继续绑定其发起时的运行时。

## 验证

检查普通重连、多个页面的账号切换、就绪等待、页面恢复和浏览器认证过期。
验证旧页面被模态提示阻止交互，只有用户确认后才导航；同一账号的普通重连自动恢复操作。
验证原生上传和日志下载不携带自定义连接标识也能成功，Workspace 文件与协同仍可使用。
账号目录恢复和远端权限检查单独验证。

本方案不要求修改 DSH 上游，也不需要新的公开传输接口。
