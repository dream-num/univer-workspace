# HTML View 指引以数据绑定为核心，设计由模型自由发挥

状态：已定（2026-11-21）。前置：[第二轮精简](streamline-round-2.zh-CN.md)、#501（风格卡）。

## 1. 结论

内置风格是为能力较弱的模型兜底的下限，不应成为能力较强的模型的上限。模型本来就擅长写 HTML，它们不知道的是
Univer 的数据绑定，这部分没有进入预训练。所以 `html-view-creator` 的主体改为数据绑定的契约和运行时语义，
设计默认由模型按数据和受众自由完成，只需满足设计下限；内置风格变成可选的起点。

## 2. 依据

- 改动前 `html-view-creator` 共 8,490 字符，约 41% 讲风格（怎么选、10 行目录、读风格卡或模板、设计下限），
  约 36% 讲数据绑定。自定义设计排在最后一档，而且必须从现成的风格卡改出来。
- 8 次实验运行的绑定样本全部正确，基础语法没有问题。出错的都是运行时语义：加载文字放进 ECharts 容器后不会被清掉；
  一个控件的占位文字依赖另一个绑定的回调状态，永远不刷新；页面自己计算达成率，算成了超额部分。
- 运行时契约（回调在 Promise resolve 之前触发、范围回调总是交付补满 null 的完整矩阵、绑定属性不改 DOM、
  各订阅没有先后顺序）只写在上游 SDK 文档里，默认路径读不到。

## 3. 决定

1. **设计默认自由。** 模型按数据和受众设计页面，满足设计下限，并在回复里说明设计和理由。内置风格在三种情况下使用：
   用户点名、模型不确定、需要稳妥基线；此时先读风格卡，数据形状接近模板原场景时再读完整模板。
2. **风格目录移出 creator。** 只留一句指向 `html_view_styles` 和 `references/design.md`。目录生成器随之删除；
   `html_view_styles` 仍从 `design.md` 的目录表解析。
3. **creator 以绑定为主体。** 依次是规则、读数据、绑定契约、运行时语义、写入、数值来源、保存结果里的绑定样本自检、
   保存与回复。详细契约只在 `references/authoring.md`。
4. **新增不带风格的最小绑定示例** `examples/binding-starter.univer.html`，默认读取：单值、表格、图表（容器保持为空）、
   带写入与成败状态的输入框、错误状态。
5. **派生指标进表，不进页面。** 页面需要的指标表里没有时，Agent 在本次会话的 PR 里给表加公式单元格（已合并的表先开 PR
   再 `unit_add`），页面绑定它，草稿带 `repo` 和 `pr` 保存，合并后页面随之上线。页面代码不计算表的指标。

## 4. 验证

两个模型、三组数据、两版指引，共 12 个页面，在隔离的 verify-uvw 实例上运行：

| 模型 | 客户端 |
| --- | --- |
| 弱：`console-deepseek/deepseek-flash#max` | opencode |
| 强：`gpt-6.1-sol`，reasoning effort `high` | Codex CLI |

数据：英雄联盟选手与战队、区域渠道周销售、项目交付任务。旧指引为 #502 之后的 `main`，新指引为本次改动。
截图交给不知道条件的评审按设计下限打分，另录滚动视频。

通过标准：弱模型新指引不低于旧指引；强模型新指引明显高于旧指引；三类缺陷（加载文字残留、页面自算指标、
首屏巨大合计条）不增加。结果补到本文末尾。
