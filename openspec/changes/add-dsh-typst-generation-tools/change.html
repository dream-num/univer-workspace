Tina Change View · add-dsh-typst-generation-tools

让 Typst bundle 进入 DSH 的本地 artifact 与 Draft 工作流

两个 operation tools 复用同一个 Core compile owner：compile 从随机 mode-0700 staging 逐文件发布；公开目录失败后保留供检查，apply 用 program-local VM 保持语义内容确定。

Scope / Non-goals

  • 仅支持 local Host 与 Session cwd。
  • 两个 tools、两个 capabilities、八个 coarse tasks。
  • Typst 路径不新增 SVG、browser、Jobs、remote FS 或通用 renderer；既有 Render closure 保持独立。

Decisions

  • 固定 artifact 目录替代 Commander 多路径组合。
  • 批准后原子预占目录并逐文件 no-clobber 发布。
  • 只清理 identity 匹配的私有 staging；公开目录失败后完整保留。
  • 同一次 Core compile 结果用于本地输出或 staged Doc。
  • apply 失败只返回 bounded diagnostics；本地失败产物由 compile 提供。
  • Node VM 只隔离 program-local random，不宣称安全 sandbox。
  • 语义比较忽略 SDK opaque IDs；持久化 UnitData 不改写它们。

Risks / Impact

  • native compile 不可硬取消，Host 必须等待并停止后续步骤。
  • 等价 materialization 的 opaque IDs 可不同，不承诺 byte-identical snapshot。
  • Unit 已确认而 artifact 失败时返回 partial side effect，不补偿重放。
  • 发布期间目录可短暂不完整；失败返回 Session-relative inspect guidance。
  • 首版不隔离同 UID 主动篡改；更强边界需独立 user/container。
  • package 新增 exact Typst native binding，不新增 worker。
