Tina Change View · add-dsh-univer-work-authentication

认证由四个 tools 发起，秘密只留在 CredentialKey

DSH 复用 Client Core 的两阶段 browser approval，以一次 start、一次 complete 建立单一 Workspace 连接，并让后续操作按次读取当前 Login Session。

Scope / Non-goals

新增 `dsh-univer-work/authentication`，修改 `workspace-client-core/auth` 的 optional signal。只支持 Host-only local、单一 active origin；一个 live Host 且无绕过它修改 owner key 的 writer是部署前提。不加入 password、authorization flow、Web Client、Settings、业务 tools 或 runtime。

Decisions

  • DSH rc.2 没有 `authorization.begin()` 产品调用方，因此采用可用的两阶段 tools。
  • 同一 Host 用 process-local queue 串行化 start、complete 与 logout。
  • fiber disposer 先停止新调用并 abort I/O，再等待 queue 与已接受 body 收敛。
  • logout 必须先获 human approval，远端失败也在 `finally` 清除本地 record。
  • private Client Core 的 reachable auth 代码内联；DSH/Cordis 使用 exact optional peers，共享 Host module identity。

Risks / Impact

取消或网络中断可能留下 `workspace-result-unknown`，禁止自动重试；credential 写入失败时丢弃 cookie。DSH rc.2 没有 owner lease/conditional delete，插件无法检测或协调其他 Host、文件或 provider writer。CLI 和 Server 行为保持不变。
